# Выбор парадигм и языков программирования

## Задача 1: Обработка больших данных в реальном времени

* **Парадигма:** Array programming и императивная 
* **Язык программирования:** C++
* **Обоснование:** Обработка изображений предполагает работу с большим количеством матриц, поэтому такой выбор парадигмы (Array programming) обеспечит выполнение операций фильтрации и поиска дефектов сразу над матрицами пикселей целиком без медленных поэлементных циклов. Выбор C++ в рамках императивной парадигмы обусловлен необходимостью непрерывной работы 24/7 без пауз на сборку мусора, а также обеспечением максимальной производительности и прямого контроля над аппаратными ресурсами.

## Задача 2: Прототип ML-сервиса для прогноза погодных условий

* **Парадигма:** Дифференцируемое и объектно-ориентированное программирование (ООП). 
* **Язык программирования:** Python
* **Обоснование:** На Python не нужно вручную писать алгоритмы с нуля — в нём уже есть огромный выбор готовых библиотек для машинного обучения. Архитектура ML построена на принципах ООП, где модели инкапсулируют веса и методы обучения, что позволяет легко заменять одни алгоритмы на другие. Внутри ML-моделей работает автоматическая подстройка параметров под данные датчиков, что избавляет нас от ручного подбора весов. Прогноз нужен всего раз в день, поэтому нам не нужна сложная компиляция и оптимизация железа, поэтому простоты и скорости написания кода на Python здесь более чем достаточно.

## Задача 3: Интерактивный UI для торгового терминала

* **Парадигма:** Реактивное программирование в рамках функционального/декларативного подхода.
* **Язык программирования:** TypeScript 
* **Обоснование:** Система разрабатывается для веба, где стандартом является TypeScript. Его строгая статическая типизация предотвращает ошибки с типами данных и обеспечивает требование лёгкой тестируемости кода. Реактивный подход позволяет работать с данными и мгновенно распространять обновления. Здесь используется декларативный подход к данным: изменение значения в одном месте автоматически обновляет все зависимые виджеты. Декларативный UI в связке с реактивными сигналами перерисовывает точечно только изменившиеся узлы интерфейса, не тратя время на полные перерисовки, гарантируя скорость обновления виджетов.

## Задача 4: Прошивка для устройства регистрации температуры

* **Парадигма:** Программирование на основе конечных автоматов (FSM — Finite State Machine) в сочетании с императивной парадигмой.
* **Язык программирования:** C
* **Обоснование:** Язык C компилируется напрямую в компактный машинный код, легко укладываясь в доступный объем памяти. Императивная парадигма и поддержка указателей в C дают возможность прямого взаимодействия с аппаратными регистрами через явные адреса памяти. Использование архитектуры конечных автоматов (FSM) позволяет разбить работу датчика на строгие фазы. Это минимизирует время активной работы микроконтроллера и экономит заряд батареи. Программа на C работает стабильно быстро и без сбоев по времени, а алгоритм датчика можно легко адаптировать под микросхему любого производителя.
